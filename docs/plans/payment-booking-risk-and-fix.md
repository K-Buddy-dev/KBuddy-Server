# 결제 고도화 문서 목록

## 1. 문서 목적

결제 고도화 작업을 구현 순서에 따라 네 단계로 나누어 관리한다. 각 단계는 이전 단계가 완료된 후 진행하는 것을 기본으로 한다.

## 2. 구현 순서

### 1단계: 동시성 제어

[결제 및 예약 동시성 제어 개선 계획](./payment-booking-concurrency-control.md)

1. `Payment`, `Booking`에 `@Version` 추가
2. 결제 승인 조회에 잠금 적용
3. 잠금 순서 통일
4. 승인·취소·입금 신고 동시성 테스트 추가

### 2단계: 멱등성 보장

[결제 및 예약 멱등성 보장 계획](./payment-booking-idempotency.md)

1. 결제 생성의 유니크 충돌을 기존 결제 반환으로 처리
2. 승인 요청 멱등키 저장
3. 이미 승인된 결제는 기존 성공 결과 반환
4. 채팅방 및 알림 생성 멱등화

### 3단계: 만료 처리

[예약 및 결제 만료 처리 계획](./payment-booking-expiration.md)

1. 예약과 결제의 만료 시간을 하나로 통합
2. 만료 상태 전이를 하나의 트랜잭션으로 구현
3. 안전한 스케줄러 활성화
4. 다중 서버 중복 실행 방지

### 4단계: 트랜잭션 분리

[결제 트랜잭션 및 외부 작업 분리 계획](./payment-transaction-outbox.md)

1. 핵심 DB 상태 변경과 외부 작업 분리
2. Outbox 테이블과 이벤트 작업자 구현
3. 알림 및 채팅방 후속 처리 재시도 구현
4. 장애 및 롤백 테스트 추가

## 3. 전체 완료 조건

- 동시 요청으로 결제와 예약 상태가 달라지지 않는다.
- 같은 요청을 반복해도 결제 및 후속 작업이 한 번만 처리된다.
- 예약과 결제가 같은 만료 기준을 사용한다.
- 여러 서버가 동시에 만료 작업을 실행해도 중복 처리되지 않는다.
- DB 롤백과 외부 알림 결과가 서로 다르게 남지 않는다.
- PostgreSQL 기반 통합 테스트가 모든 단계를 검증한다.
